# Quality-Gated V5 Provenance, Freshness and Non-Regression Contract V1

## Status

This branch introduces a research-only, projection-only contract over the 3,562-trade
official universe. It does not train Qlib or IA Shadow, does not rebuild Phase 5,
does not rematerialize candles, does not write candidate or official Parquets, and
does not change runtime, risk, registry, services, signals or models.

## Problem addressed

The previous `build_quality_gated_shadow_compatible_dataset_v1.py` entrypoint:

- recognized only historical OCR provenance markers;
- accepted feature snapshots without a freshness gate;
- accepted `merge_asof` snapshots with no temporal tolerance from `trade_enriched`;
- wrote candidate/full-audit Parquets before completing validation;
- used a fixed row-count threshold instead of set-based identity comparison;
- collapsed row quality into a single reason string.

The V5 tail requires an explicit provenance pair:

```text
source_file =
bitradex_ocr_locked_candidates_20260714_151816_time_repaired_orderid_synthetic_v5

ocr_source =
bitradex_black_rectangles_time_repaired_orderid_synthetic_v5
```

No broad substring matching, positional inference, tail-size inference or synthetic
`order_id` inference is permitted.

## Architecture

```text
trade_enriched + market_features + official quality-gated + model SHA-256
    -> exact provenance classification
    -> snapshot availability/freshness
    -> 74-feature construction and lineage diagnostics
    -> feature-name and temporal anti-leakage
    -> deterministic multi-reason eligibility
    -> conservative official/projected identity audit
    -> JSON / JSONL / Markdown research evidence
```

## Freshness semantics

The contract treats stored candle timestamps as candle-open timestamps.

```text
snapshot_available_at = snapshot_time + timeframe_duration
snapshot_available_at <= trade_open_time
snapshot_age_seconds = trade_open_time - snapshot_available_at
```

Default maximum ages:

```text
1m: 120 seconds
5m: 600 seconds
```

The following conditions block a row even when all model features are finite:

- missing snapshot;
- future snapshot;
- in-progress candle;
- stale snapshot;
- unknown timestamp semantics.

The real-data audit established that finiteness is not proof of temporal availability.
A row remains blocked when a feature came from a candle that had not closed at trade
entry time.

## Model contract

The model is never deserialized. Its file is read only as bytes to verify SHA-256.

```text
expected model SHA-256:
b5599c0d09881051b0e4456a9b3e94a38a10c4ecd1f0f14e37f736c2f9d083d4

feature count:
74
```

Feature families:

- 16 `prior_1m_*`;
- 16 `prior_5m_*`;
- 16 `meta_*`;
- 13 `v13_1m_*`;
- 13 `v13_5m_*`.

No imputation, unlimited forward-fill or feature fabrication is performed.

## Multi-reason eligibility

Every row contains:

```text
eligibility_status
primary_reason
block_reasons
warning_reasons
eligible_for_research_training
eligible_for_model_training
```

`primary_reason` is chosen by deterministic precedence. All secondary blockers remain
preserved in `block_reasons`.

Data eligibility does not authorize training. This branch always reports:

```text
training_requested=false
training_performed=false
qlib_training_performed=false
ai_shadow_training_performed=false
```

## Identity and non-regression semantics

### Artifact identifiers are not automatically canonical

The official quality-gated artifact and the reconstructed `trade_enriched` universe
may contain `trade_id` values generated by different pipeline versions. A zero-overlap
set comparison does not prove that official trades disappeared.

The real-data audit observed:

```text
official unique trade_id: 2737
universe unique trade_id: 3562
artifact trade_id overlap: 0
```

This result proves an incompatible or unproven artifact identity namespace. It does
not prove identity loss.

### Canonical authority conditions

The branch grants non-regression authority to artifact `trade_id` only when:

```text
both artifacts expose trade_id
both identity populations are non-empty
at least one exact trade_id is shared
trade_id is unique in the official artifact
trade_id is unique in the universe artifact
```

When these conditions are not met:

```text
nonregression.status=blocked
nonregression.reason=canonical_identity_unavailable_for_official_artifact
canonical_identity_computable=false
canonical_nonregression_evaluable=false
official_identity_loss_proven=false
official_identity_retention_proven=false
unexplained_removed_official_ids=null
```

`null` means that the unexplained-removal gate was not evaluable. It must not be
rendered as zero, because zero would incorrectly imply that the gate was evaluated
and passed.

### `order_id` is diagnostic only

The real-data audit also observed partial `order_id` continuity:

```text
order_id overlap: 2117 / 2737
missing official order_id keys: 620
universe duplicate order_id rows: 31
```

This evidence is useful for lineage diagnostics but has no canonical identity
authority. The artifact does not prove a common `order_id_namespace`, and duplicate
values exist in the universe.

The report therefore exposes:

```text
order_id_diagnostic_overlap_unique_keys
order_id_diagnostic_missing_official_keys
order_id_diagnostic_official_duplicate_rows
order_id_diagnostic_universe_duplicate_rows
order_id_has_identity_authority=false
```

### Existing Trader Master fingerprint contract

The repository already contains `trader_master_fingerprint_spec_v2`. This branch does
not create a competing fingerprint. The existing specification requires source,
market, contract, account-scope, temporal, price, quantity and financial lineage that
is not fully persisted in the current official quality-gated artifact.

The official quality-gated file exposes `trade_id`, `order_id`, `symbol`, `side`,
`open_time_utc` and `reported_pnl_usdt`, but does not expose enough fields to rebuild
the full canonical Trader Master fingerprint or the complete legacy observation key.

### Set-based gate when identity is evaluable

When a shared unique identity namespace is proven, the projection computes:

```text
official_trade_ids
projected_trade_ids
retained_official_ids
blocked_official_ids
newly_eligible_ids
newly_blocked_ids
official_ids_missing_from_universe
unexplained_removed_ids
```

Primary gate:

```text
UNEXPLAINED_REMOVED_OFFICIAL_IDS=0
```

An explained reduction caused by freshness or anti-leakage is reported as
`review_required`; it is not silently promoted and is not treated as defective merely
because the count is lower.

When canonical identity is unavailable, the artifact-level lists remain diagnostic
only. Per-row `official_membership` is also an artifact `trade_id` diagnostic and must
not be interpreted as canonical historical membership.

The contract must prove, rather than assume:

- universe rows: 3,562;
- V5 provenance recognized: 504/504;
- no duplicate universe `trade_id`;
- stale/future/in-progress snapshots are never accepted;
- the exact number of eligible rows is evidence, not a target;
- identity loss is never inferred from incompatible artifact namespaces;
- missing `prior_5m_*` is distinguished from absent raw 5m coverage.
